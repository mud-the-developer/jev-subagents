# Measurement contract: reference audit and gates for a valid next study

## What actually ran here

This directory implements a **retrospective, zero-provider audit** of the existing10-question/30-workflow metadata. It computes paired statistics, disjoint recorded time/cost accounting and an explicitly hypothetical fixed-workflow-bank comparison. It does not run a new agent, repair a gold query, change an old score, certify semantic SQL correctness or produce a coding leaderboard score. See [REFERENCES.md](REFERENCES.md) for primary-source sections and limits.

## Separate three questions

1. **Routing component:** given comparable candidate models/roles and enough current-task evidence, does a policy improve the quality–cost frontier relative to always-cheap, always-strong and a matched random mixture?[R1,R2]
2. **Workflow/harness:** holding tasks, stage structure, tools and environment constant, what does the routing/scaffold add? Separately, does an optional multistage workflow improve outcomes enough to pay for additional sessions/handoffs? Do not confound both changes.[R3]
3. **Coding ability:** can the deployed agent resolve real repository tasks under the official repository/test environment? SQL or multiple-choice answers cannot answer that question; a canonical coding harness such as SWE-bench has a separate environment/grader contract.[R6]

## Statistics implemented now

- `analyze.py` reads only published whitelisted historical metadata, verifies10paired task IDs/30completed rows and source SHA, and runs assert self-tests.
- Exact two-sided McNemar uses the binomial probability of discordant paired outcomes.[R8] All current pairwise tests return p=1; this is **not equivalence or proof of equal semantic quality**.
- Paired task bootstrap uses10000resamples, seed0x6A09E667, same indices across paired metrics, explicit95%percentile intervals.[R7,R9] It is conditional on one recorded trial per case/policy, with nominal/unadjusted exploratory coverage—not a claim to model-generation uncertainty or a full production-latency distribution.
- A1024-choice enumeration mixes the two **recorded fixed workflows** for the10cases, yielding a random-half expectation and an ex-post gold oracle. It never executes another model or claims a live stage policy, measured oracle latency or an official RouterBench score.[R2]
- Time components are algebraically disjoint at the top level; child startup/generation breakdown is nested and not added again. Generation includes tool/freshness/cleanup work; parent envelope mixes import/IPC/Job/exit. There is no pure API/native-security timing separation in the old data.

## Deliberately not claimed

No new holdout/model trial, canonical SWE-bench score, corrected semantic accuracy, statistically proven routing regression, quality-preserving production speedup, independent model-tier ranking, calibrated success probability, paid invoice validation or authority to execute the next study. A valid new live run needs the applicable environment, grader/contracts and closed trial budget first. The references are justification for these gates, not permission to bypass them.
